# P01-01 V1 需求索引与后续追踪入口

> 状态：高层范围基线。详细功能 Schema、指标及完整测试矩阵分别在 P01-02、P01-03、P01-04 拆解。本文件不得用于声称功能已经实现。

## 优先级和验证规则

- `MUST`：V1 必须可运行或明确被外部阻断并进入 `PARTIAL_DELIVERY`；不能以样例/文档冒充通过。
- `SHOULD`：不应阻挡核心业务验收；若不实现须提供理由与后续任务。
- `OUT`：明确不在 V1 执行范围，Codex 不得擅自实现。
- 任何与钱、成交、价格、交易日历、风控有关的计算必须由确定性程序实现并留下可重复验证证据。
- 当权限、数据、行情、回测或账本缺失时，保留 `NOT_VERIFIED` / `BLOCKED_EXTERNAL` / `DEMO_ONLY` 的准确状态，不补造缺失内容。

每条细化需求最终至少包含：

1. 需求 ID、来源与业务意图。
2. 正常触发、输入、前置状态与异常路径。
3. 数据源和真实/延迟/历史/Fixture 状态。
4. 精确定义的通过条件及失败门禁（含时区和币种）。
5. 设计/接口章节与相关 Issue。
6. 测试用例 ID、类型（unit/integration/e2e）、实际执行结果及证据路径。

## 设计待决事项

- 市场数据服务商及不同授权等级；P04 应验证后才决定具体 API。
- 日报/扫描频率与任务时间点：需要可配置，不能以开发机现在时间作为固定默认。
- 是否允许内网访问及系统通知授权：在 P02 威胁建模和 P01-04 NFR 确定；当前按本机回环地址单人使用，不设应用登录、口令或用户管理。
- 紧急/半日交易所特殊休市的获取方式：P07 需要版本化数据及人工审核覆盖机制。
- 财报/新闻来源的内容使用权与数据频度：不得未经许可通过爬取绕过服务限制。
