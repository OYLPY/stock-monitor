# FR-Research — 晨报、异常监控与研究报告契约

> 状态：P01-02 需求基线；这是拟实现和验收的契约，不代表行情、新闻或 AI 接口已经接通。对应 [Issue #21](https://github.com/OYLPY/stock-monitor/issues/21)。
>
> 上位约束：[PRD](PRD.md)、[需求索引](REQUIREMENTS_INDEX.md)、[用户用例](USE_CASES.md)。本产品是个人本地即开即用工具，无应用登录、注册、用户管理、云端身份或 SaaS 账户依赖。

## 范围与术语

- 市场范围为 NYSE、Nasdaq 和东京证券交易所（TSE/JPX）普通股票与非杠杆 ETF。研究晨报、盘中异常监控、日/周研究审计均可在本机手动运行或由本地 Worker 触发。
- 事实是来源明确支持的陈述；假设是待验证的策略主张；推论是基于事实作出的解释。报告必须区分三者，不得把模型解释写成来源事实。
- 报告任务状态、证据验证等级、数据新鲜度和扫描结果是不同维度，不得互相替代。Fixture 的演示结果不属于实盘行情或历史绩效。
- 本 Issue 定义行为和验收契约；具体数据供应商、扫描间隔、阈值及持久化状态机留给 P02–P04/P07/P08 决定或验证，不在本文件猜定。

## FR-Research-001 / 002 — 交易日历与监测窗口

### 日历输入与时区

1. NYSE 和 Nasdaq 分别维护市场日历，使用 IANA 时区 **America/New_York**；不得固定写成 EST 或用开发机时区代替。TSE 使用 **Asia/Tokyo**。
2. 日历记录至少包括交易所、有效日期、当地时区、常规时段、午休区间（如有）、提前收盘/临时休市、官方来源引用、采集时间及可获得的来源版本或更新时间。
3. 常规时段以官方交易所日历为准：[JPX 现金股票交易时间](https://www.jpx.co.jp/english/equities/trading/domestic/01.html)、[NYSE 交易时间与日历](https://www.nyse.com/trade/hours-calendars)、[Nasdaq 交易时间与假期日历](https://www.nasdaq.com/market-activity/stock-market-holiday-schedule)。使用官方公布的例外时段，不把盘前、盘后或提议中的延长时段计入 V1 常规窗口。
4. 窗口按当地时间左闭右开解释：开盘时刻符合扫描条件，收盘时刻不符合。DST、周末、节假日、临时休市及提前收盘均由交易所当地日历换算，不自行枚举固定 UTC 偏移。
5. TSE 现金股票常规时段为 09:00–11:30、12:30–15:30 JST；11:30–12:30 是午休，不属于监测时段。NYSE/Nasdaq 核心常规时段为 09:30–16:00 America/New_York；各自例外日历优先。

### 扫描门禁

- 调度触发或手动请求均必须经过相同门禁。若所有目标市场均不在常规时段，结果为 **SKIPPED_CLOSED**，不得采集为“已完成扫描”，也不得发“无新事件”或市场平静提醒。
- 若某一目标市场开放，只能对该开放市场上市的目标证券执行盘中行情/证券异常监测；其他休市市场的证券保持非盘中状态。跨市场宏观事件只能作为当前开放市场的研究背景，不得伪装成休市证券的盘中价格观察。
- 当前市场处于午休、提前收盘或临时休市时，依对应日历判定，不按常规钟点猜测。
- 无法确认日历是否有效或例外安排时，失败关闭为 **CALENDAR_UNAVAILABLE** 并禁止盘中扫描；不能假定开市，也不能报告 **NO_NEW_EVENTS**。
- 晨报、日/周研究审计不受盘中时段限制；报告须逐交易所区分最近一个**已完成**常规交易日，不得用尚未结束的时段充作收盘数据。

## FR-Research-003 / 004 / 005 — 事件资格、新旧与去重

### 重大性与证据

事件仅当有来源支持的事实可能实质影响目标证券现金流/资本状况/上市或监管状态、市场利率/汇率/流动性/风险环境，或使现有研究假设、策略失效条件、纸面计划风险发生变化时，才可列为“重大”。仅有情绪、重复标题或无法由证据支持的因果猜测不构成重大事件。

每项候选必须记录受影响市场/证券、事实摘要、来源证据、时间、重要性理由，以及单独标记的影响推论和不确定性。来源缺失或无法验证的内容不能晋升为已核实重大事件。

### 新事件、迟到发现和修订

- 事件首次出现与最后成功扫描水位比较；事件只有在前一轮成功结果已持久化后才推进水位。失败、超时或不完整抓取不得推进对应来源的成功水位。
- 优先使用来源稳定 ID；没有稳定 ID 时以规范化标题/主体、事件类别、目标实体及已知发生时间形成跨来源事件簇。具体规范化和持久化算法由 P03-05 定义。
- 同一事实的转载、标题改写或多个来源报道归为同一事件簇；已通知事件静默，不重复提醒。来源增加但事实未改变只更新证据列表。
- 新的权威信息实质改变事件事实、影响范围或风险判断时，保留原记录并作为重大修订更新；不得覆盖历史或重复计作全新事件。
- 事件较早发生/发布、在本轮才首次发现时，标记 **LATE_DISCOVERY** 并保留在历史记录；超过来源与事件类别配置的已验证时效 SLA 后，不作为实时异常提醒。供应商尚未选择或 SLA 未经验证时，不宣称实时新鲜度。
- 超过单轮 3 项限制的候选记为 **DEFERRED_LIMIT** 并保留。未通知的候选仅在仍满足新鲜度与重大性条件时可在后续扫描递补；过期候选记为 **EXPIRED_UNNOTIFIED**，不静默删除、不补发为实时事件。

### 每轮上限及稳定排序

扫描最多产生 3 个新的通知事件。排序依次为：直接触发已记录的纸面风险/策略失效条件；直接涉及目标证券或开放市场；来源质量与证据完整度较高；较新的市场发生/来源发布时间；最后以稳定事件 ID 打破平局。排序依据及超额数量须留档，重跑同一输入结果保持一致。

## FR-Research-006 / 010 / 011 — 溯源、时效和状态

### 来源记录字段

每条来源或报告事实至少携带：

- 来源名称、来源类型/引用 URL 或本地引用 ID、稳定来源记录 ID（若存在）。
- **publishedAt**（来源发布时间）、**occurredAt**（事件发生/市场时间，若可知）、**collectedAt**（本机采集时间）；同时保存时间精度和适用时区。
- 行情数值若适用，记录证券/市场、报价市场时间、币种、单位、供应商声明的延迟等级。
- 来源可靠性等级及其判定依据、来源覆盖状态、质量/时效判定、原始值与解析错误/冲突摘要。可靠性等级需按经核验的来源规范确定，不能由标题或流行度推断。未知值必须留空并附 **NOT_VERIFIED** 原因，不推测时间、币种或可信度。

时效 SLA 必须按来源/数据类别配置，并在 P04/P07 选定供应商及验证后才可启用实时声明。超过 SLA 的输入为 **STALE**；未配置或无法判断时效时为 **UNKNOWN**，两者均不能生成实时触发信号。**DELAYED** 表示来源明确声明延迟，不等同于新鲜或过期。

### 相互独立的状态维度

| 维度         | 值                                                                                                                | 语义                                                                                                                                                                                                               |
| ------------ | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 任务执行     | PENDING、RUNNING、DONE、FAILED、BLOCKED_EXTERNAL、SKIPPED                                                         | 执行生命周期沿用 UC-09 和 P03-05 状态机；BLOCKED_EXTERNAL 是执行/依赖状态，不是证据等级。                                                                                                                          |

## FR-Research-007 / 008 / 009 — 工作流与报告

### 晨报工作流

1. 记录生成时间、报告 asOf 时间和时区，逐一解析 TSE、NYSE、Nasdaq 的日历及最近已完成交易日。
2. 收集可用的日美市场收盘上下文、汇率/利率、未来 24 小时经济日历和已有研究候选。经济事件窗口定义为 [asOf, asOf + 24h)；每个时间值保留来源时区与换算时间。
3. 先生成有来源的五行市场摘要和事实列表，再分别列出策略假设、证据、未验证缺口及对手情形。
4. 至多呈现 3 个不同研究逻辑；无通过条件者可为空，不为满足数量而造策略。策略研究不等于计划获批或模拟成交。
5. 独立确定性风险组件对计划输出 APPROVED_FOR_PAPER_REVIEW、REJECTED 或 UNRESOLVED 及原因；输入不足时为 UNRESOLVED。此裁决不执行订单，AI 不得覆盖裁决。
6. 明示纸面账本为 INITIALIZED、NOT_INITIALIZED 或 UNAVAILABLE；不存在或不可读时不推算权益、持仓、订单或盈亏。

### 盘中异常扫描工作流

1. 记录目标市场、日历版本/有效性、扫描窗口、上次成功水位和本轮时间。
2. 执行交易日历门禁，再采集各开放市场允许的事件和行情来源；逐项检查覆盖、时间戳、来源状态、时效和事件身份。
3. 排除重复/不重大事件，将事实和影响推论分开，按稳定规则排序并限制最多 3 个通知；迟到、递补、超额和去重结果保存在审计记录中。
4. 按来源完整度返回扫描结果。只有所有必需来源完整且有效、无新重大事件时才可返回 NO_NEW_EVENTS；休市、日历失败、来源缺失、数据过期分别使用对应状态。

### 日度/周度研究审计工作流

- 日度审计检查已有候选、验证证据、策略条件/失效原因及独立风险裁决；周度审计比较可复核的研究变化、已验证的模拟记录和未解决假设。
- 没有真实可复算市场数据时，不报告历史绩效；没有连续可核验模拟账本时，不报告账户收益、周盈亏或持仓变化。缺口写入报告并限制验证等级。
- 六研究角色可以在同一 AI 工作流中分工；其输出必须回链证据，且不得访问写入权限以修改风控结果或账本。

### 报告导出

报告可导出为文本、Markdown 或 CSV，并附来源摘要。导出不得丢失市场/采集时间、时区、币种、来源引用、延迟/历史标记、验证等级和 Fixture 标记；CSV 不得把 Fixture 或未验证字段伪装为真实数值。导出范围不能暗中包含密钥。
