## 1. 产品定位

**Quant Research Workbench** 是运行在用户自有计算机上的、美股与日股的 **AI 辅助研究 + 可复算量化验证 + 独立风控 + 纸面模拟** 工作台。它不是券商、交易终端、自动交易系统，也不保证投资收益。

产品要解决的核心问题并非“每天产出交易建议”，而是让研究过程具有可验证的证据链、可重复的统计验证、明确的禁止操作边界及能长期保存的执行记录。

### 1.1 目标（按优先级）

| ID | 产品目标 | 可观察的成功条件 |
|---|---|---|
| G-01 | 可信的美日市场上下文 | 用户能辨认最新**已完成**交易日、当地时区、数据源、延时与不可验证状态 |
| G-02 | 过滤新且重要的市场异常 | 非交易时段不运行盘中扫描，重复/无证据消息不发重大提醒 |
| G-03 | 证据驱动的 AI 策略研究 | 每个策略说明经济假设、对手盘、触发/失效条件、风险与验证状态，不杜撰回测 |
| G-04 | 独立、确定性的纸面风控 | 风控计算可重算；突破2%或达到20%账户回撤阈值时阻断新增头寸 |
| G-05 | 可恢复的本地持久化 | 模拟账本与任务记录在进程中断及重启后可复核；不能只存在 AI 上下文 |
| G-06 | 尽量减少人工操作 | 日报/盘中监测/日审计/周审计由本地 Worker 在可用条件下执行，失败可审查和恢复 |

### 1.2 不承诺的事项

- 不承诺任何股票预测准确率、收益、自动发现盈利策略或长期 24×7 不间断在线。
- 不保证联网数据“实时”；需要数据提供商逐项验证价格频度、覆盖与授权。
- 不宣称六个研究角色是六个独立部署的 AI Agent；可以是同一个 Codex 任务内的职责步骤。
- 不实现交易所直连、真实券商账户登录、真实订单发送、自动入金、信用交易、保证金、杠杆 ETF、期权、卖空或资金转账。
- 不把联网搜索、AI 输出或模拟 Fixture 当成未经核实的事实/市场成交。

## 2. 目标用户与运行环境

### 2.1 用户与权限边界

| 角色 | 职责 | V1 范围 |
|---|---|---|
| 本地主人（Research Owner） | 配置数据源、研究任务、确认研究范围、审阅/批准纸面计划、审计风险 | 唯一业务用户；本机即开即用，不设应用登录、注册、用户管理或 RBAC，也不设 SaaS 多租户/订阅。Codex CLI 认证仅供开发者 Autopilot 运行器使用，不作为应用访问条件 |
| 调度 Worker | 在本地执行符合交易日历和调度规则的研究任务，记录状态与失败 | 操作系统提供生命周期管理；不能自行突破授权 |
| Codex 研究运行器 | 联网材料整理、结构化分析、解释候选策略与研究结论 | 按批准的输入和能力调用；不能直接写资金、订单及账户余额 |
| 确定性风控/模拟引擎 | 计算风险、可用资金、模拟成交、账本权益 | 代码实现与可复算测试，不依赖模型主观确认 |
| 外部数据提供方 | 提供行情、公告、财报、经济数据 | 可插拔；未配置、过期或失效时显式降级 |

产品不提供用户/管理员身份体系；本机用户由设备操作系统区分。设备所有者不等于真实证券交易账户管理员。

### 2.2 运行约束

- 主界面：Next.js + React + TypeScript，默认简体中文，保留未来国际化扩展位。
- 本地服务：Next.js Node 运行时；独立 Node Worker 承担计划任务；SQLite 保存可审计持久化数据。
- 本地 AI：优先 Codex SDK；是否能成功鉴权、调用、联网搜索及成本取决于实际开发环境与官方支持。**这些是 P04 技术验证项，P01 不预先宣布通过**。
- 设备休眠、关机、网络断开、模型额度/授权不足时不得声称持续监控；可记录错过的窗口并在恢复后按规则补偿非盘中任务。
- 默认绑定本机回环地址；Web 前端不得持有 Codex 密钥或外部数据源的敏感访问凭据。
- 初始版本仅支持个人单机本地使用；多设备同步和云端 SaaS 不在范围内。

## 3. 固定业务边界（MUST，任何任务不得放宽）

| 编号 | 规则 |
|---|---|
| BR-01 | 市场范围：美国和日本交易所上市普通股票与**非杠杆 ETF**；不使用选项、做空、杠杆或保证金。 |
| BR-02 | 纸面账户在用户显式初始化时记录初始资金 **1,000,000 JPY**；没有账本时显示“未建立”，不得虚构此前记录。 |
| BR-03 | 每笔拟议交易的预计最大损失必须 ≤ **可核验当期模拟权益的 2%**（初始为 JPY 20,000）；未能核验权益或损失时不得批准新仓。 |
| BR-04 | 以历史权益峰值计算账户最大回撤；**达到或超过 20% 时停止新增模拟头寸**，必须标注审计状态。 |
| BR-05 | 每笔交易周期由可验证的策略假设决定，可为日内、波段或中长期；不得强制每天满仓或产生三个信号。 |
| BR-06 | TSE 常规交易：09:00–11:30、12:30–15:30 JST；NYSE/Nasdaq 常规交易：09:30–16:00 America/New_York；同时处理 DST、周末、交易所节假日和特殊提前收盘/临时休市。 |
| BR-07 | **只有至少一个目标市场处于常规交易时段才运行盘中异常扫描**；均休市时跳过且不发“重大异常”提醒。研究晨报和回测不必限于开盘时段。 |
| BR-08 | 当有确切、重大、新且可能改变研究结论/风险的证据时，异常通知最多包含 3 个互不重复事件；没有证据的变化不推断。 |
| BR-09 | 行情与事件必须记录来源、发布时间或市场时间、采集时间、时区、币种与来源可靠性/延迟；没有最新可验证数据不能生成实时交易触发信号。 |
| BR-10 | AI 不能声明自己读取未授权的 TradingView/券商图表，也不能以自然语言给账本写入“已成交”。 |
| BR-11 | 所有自动化交易相关结果仅是待审核纸面计划；任何真实交易、券商连接或付费操作必须经过用户单独批准，并且 **V1 不提供真实交易执行能力**。 |
| BR-12 | 风控独立于策略建议，具有否决权；未达到统计验证证据门槛不得凭模型打分通过。 |
| BR-13 | 无持续可核验账本时不可展示具体持仓、净值曲线、已成交订单或累计收益的断言。 |
| BR-14 | 研究支持不执行任何模拟计划，允许空仓及暂停；策略研究/报告的执行不代表纸面交易被执行。 |

详细金融公式、订单与股数边界由 [P01-03](https://github.com/OYLPY/stock-monitor/issues/22) 定义；本 PRD 只确立不可违反的上位规则。

## 5. 核心研究周期与四类任务

### 5.1 每日晨报（Morning Research）

- **触发：**用户从 UI 手动生成；或本地 Worker 根据可配置时间表启动。
- **输入：**上一个各自**已经完成**的日美常规交易日、可信行情/财报/宏观数据、未来24小时事件、已有候选策略与可核验账本状态。
- **输出：**五行市场摘要、汇率与利率背景、已发生/未发生事件、最多3个研究策略及数据证据缺口、独立风控意见、账本状态、一句话决定。
- **失败/降级：**节假日/周末标注交易日；美股未收盘不得叫“已完成”；数据源失败则报告 NOT_VERIFIED；AI不可用时保留失败日志，不生成似是而非的报告。
- **校验：**实际来源/时间戳与交易日边界准确；不必强行产出3个候选。

### 5.2 盘中异常（Market Anomaly Watch）

- **触发：**本地 Worker 在至少一个目标市场的**常规交易时间**内执行；UI 可手动请求检查，但同样遵循窗口门禁。
- **输入：**交易所日历、候选标的、上次观察时间、新闻/公告/行情的可验证来源及最新时间戳、当前策略失效因素。
- **输出：**最多3个真正新且重大事件，每个包含市场/证券、事件市场当地日期时间、事实、研究冲击、触发/失效条件、风险与建议动作；无新重大项则静默。
- **失败/降级：**双市场休市不运行盘中采集；来源缺失或行情过期时仅记数据不可用状态，不把无数据当作无事件；同一新闻重复报道不得重复通知。
- **校验：**交易时段和事件去重可由 Fixture 重播验证。

### 5.3 每日策略研究与模拟计划审计（Daily Strategy Audit）

- **触发：**用户手动或每日计划任务。
- **输入：**现有研究候选、历史价格/成交量、交易成本、市场事件、模拟账本及风控审计数据。
- **输出：**至多3个经济逻辑不同的策略，记录对手盘、优势假设、具体入场/退出/止损、ATR/波动逻辑、可成交性、风险金额和风控批准/否决。
- **验证：**五维各1–5分：样本外稳定、扣费后收益、最大回撤、成交可行性、跨环境稳健；证据不足时不赋分，只有真实证据支持达到18/25以上方可标记**验证候选**，不是自动下单许可。
- **失败/降级：**无同步 OHLCV/ATR 不给实时报价或股数；无持久账本不计算现有资金权益；实际回测未执行不得报告交易次数/收益。

### 5.4 每周审计（Weekly Research Audit）

- **触发：**用户手动或每周 Worker 计划。
- **输入：**最近一周研究/事件/验证历史、回测配置和运行证据、模拟账本、失败数据源及未解决阻断。
- **输出：**假设的有效/失效证据、新发现的风险与偏差、待验证项目、可执行研究下一步；可按数据充分性将策略降级或维持观察。
- **失败/降级：**样本不足、无绩效账本、无历史数据时只记录欠缺，不生成周收益或“历史已验证”的评价。

以上 4 项任务彼此独立，可停用单项调度。**盘中扫描与非盘中研究任务使用不同的市场门禁**；不得把前者的条件误用于后者。

## 6. 六角色职责分界

| 角色（可以是同一次 Codex 研究的步骤） | 输入 → 产生的工作产物 | 不能执行 |
|---|---|---|
| 统筹 Coordinator | 任务要求与证据覆盖 → 任务范围、研究结论与缺口 | 通过口头命令覆盖固定风控 |
| 情报侦察 Intelligence | 原始公告/宏观/财报/报道 → 带时间戳的事实及来源 | 猜测未采集到的行情 |
| 市场结构 Market Structure | 可验证OHLCV与事件 → 趋势/波动/异常证据及无数据声明 | 假装实时图表访问 |
| 策略研发 Strategy Research | 事实+统计结果 → ≤3策略假设、触发/失效和测试要求 | 以无样本“胜率”作为盈利证明 |
| 独立风控 Risk Officer | 候选策略+确定性风险计算 → 准入、否决、风险缺口 | 忽略2%/20%等强制条件 |
| 模拟交易员 Paper Planner | 审批结果+撮合规则与账本 → 纸面计划/状态/报告 | 写入未满足成交规则的成交，或向券商下单 |

风控计算和模拟成交引擎属于**确定性代码**，不是“独立风控角色”一段模型话术的替代品；角色输出要经过代码校验。

## 7. UI 信息架构

主要导航（V1）：

1. **总览 Dashboard**：日美市场开闭市、最近完成交易日、来源健康、最近研究任务、风险提醒和模拟账户摘要（若存在）。
2. **市场与事件 Markets / Events**：行情时序、时间戳、市场状态、重要事件、原始来源、去重标识与筛选。
3. **研究晨报 Reports**：每日晨报、AI研究依据、经济日历、报告归档、导出。
4. **策略实验室 Strategies**：候选逻辑、历史回测实验、参数、成本、样本外证据和五维验证门禁。
5. **纸面账户 Paper Trading**：账户初始化、候选/审批、模拟订单/流水、权益与峰值回撤；无账本时空状态。
6. **任务中心 Tasks**：四类定时任务、执行历史、错误、重试与静默通知规则。
7. **设置 Settings**：本地 AI 接入状态、数据源、交易日历更新、备份/恢复及开发 Fixture 模式。

跨页面公共元素：**市场当地时间及 JST、来源、采集/发布时间、币种、实时/延迟/历史/Fixture/NOT_VERIFIED 状态**；当时效无法保证时必须明确警示。

## 8. 联网、离线和异常模式

| 场景 | 能做什么 | 必须禁止/明确表达 |
|---|---|---|
| 网络正常 + 数据源有权限 | 按供应商范围采集事实、运行条件合格的研究及统计回测 | 不把延时价格称作实时；不越权访问付费端点 |
| 网络正常 + 部分 API 缺密钥 | 展示来源状态、使用可用公开资料和已缓存历史；继续离线开发测试 | 缺关键市场价格时不得给实时信号或模拟成交 |
| 断网 + 本地已有合法历史数据 | 浏览已缓存报告/账本，运行不依赖实时数据的历史测试、导出备份 | 不把旧数据升级为当前；不能产生新的实时重大事件通知 |
| Codex SDK 未认证/额度不可用 | 显示研究服务不可用，继续确定性计算和本地数据操作 | 不生成假的 AI 研究结论或声称模型已运行 |
| SQLite 未初始化 | 显示“未建立共享纸面账本”，提供显式初始化流程 | 不推断当前余额/回撤/收益/持仓 |
| 数据源返回 Fixture | 能在显著标记的 DEMO 模式演示完整界面及测试工作流 | 不可与 REAL 模式合并记账或在正式研究报表中伪装真实性 |
| 本地 Worker 退出或设备休眠 | 在重启后审计错过任务、重试非时效任务并记录失败 | 不回补已经错过的“盘中即时监测”为当时在线发现 |
| 价格/新闻日期冲突 | 保存冲突证据及来源、标记需确认 | 不自行任选一个数值作为确定事实 |

### 8.1 核心数据/任务状态词汇

- `VERIFIED`：可追溯到实际获取的来源、证券/时间/币种及有效性检查，不代表该来源一定无误。
- `NOT_VERIFIED`：缺少足够来源、样本外统计或无法计算的状态；不能按交易信号处理。
- `DELAYED` / `HISTORICAL`：延时或历史数据，不允许自动提升为实时行情。
- `DEMO_ONLY`：显著标记的 Fixture 数据运行结果，不能进入真实研究/纸面成交账本。
- `BLOCKED_EXTERNAL`：缺少外部认证、授权、费用批准或必需服务；保持外部依赖未通过状态。
- `SKIPPED_CLOSED`：目标市场全部不在常规交易时段，本轮盘中扫描未执行，并非“已扫描且没有信号”。

各状态的完整转换、错误语义和持久化规则由 P03/P05 实现，本节仅统一跨页面的产品语义。

## 9. 核心端到端用户旅程

详细流程图和每条路径的触发/输入/结果/失败见 [USE_CASES.md](USE_CASES.md)。下表为产品层概览。

| UC | 用户想完成的事情 | 正常完成定义 |
|---|---|---|
| UC-01 | 首次本地启动并配置 | 无需应用登录、注册或用户管理即可进入本地工作台；Codex CLI 认证仅用于开发者 Autopilot，与应用访问无关 |
| UC-02 | 阅读当日晨报 | 了解两个市场最近完成交易日、事实来源、≤3个研究候选和风控结论 |
| UC-03 | 只收到重要盘中异常 | 交易窗口内仅收到可核实的新重大事件，无变化保持静默 |
| UC-04 | 复核日度策略 | 看到策略条件、实证或 NOT_VERIFIED、风控裁决与未批准交易计划 |
| UC-05 | 执行每周研究审计 | 获得假设检验和风险/数据缺口的可追溯总结 |
| UC-06 | 审阅策略数据来源 | 可跳转对应原始证据、查看时间戳与数据冲突提示 |
| UC-07 | 初始化纸面账本并尝试模拟计划 | 明确区分计划、批准、模拟订单与真实数据触发的模拟成交 |
| UC-08 | 进行历史回测与压力测试 | 获取可复算实验或数据不足/未验证结果，不产生虚假统计 |
| UC-09 | 查看/恢复本地任务 | 能分辨正在执行、失败、外部阻断、已完成、跳过及手动恢复 |
| UC-10 | 备份或恢复本地数据 | 保持资金流水和任务审计完整，恢复结果可核查 |

## 10. 成功衡量（定义，不预填数值）

V1 不以“模拟赚了多少钱”为核心 KPI，而使用以下可审计指标：

- **数据可信性**：研究报告中具有来源、市场时间、采集时间、币种的数据覆盖率；NOT_VERIFIED 的正确呈现率。
- **事件质量**：重复事件误报率、无证据重大提醒数量、非交易时间误触发盘中扫描次数。
- **运行可恢复性**：任务重启后重复执行数量、丢失/损坏账本事件数量、外部失败被正确降级数量。
- **研究可信度**：策略五维评分中有可追溯样本外结果的比例、回测重播一致性、对照2020/2022历史压力的执行覆盖率（前提是历史数据可用）。
- **风控完备性**：2%/20%边界拒绝测试、账本事件幂等/金额守恒、无真实券商调用入口。
- **可使用性**：离线首页可见、主要导航通达、出错可恢复、空数据与延迟数据清晰。

指标的确切阈值与测量技术属于 [P01-04](https://github.com/OYLPY/stock-monitor/issues/23) 和 P12，不在本 Issue 臆造测试成绩。

## 11. 关键依赖与风险假设

| 类别 | 风险/未知 | 待验证/行动 |
|---|---|---|
| Codex SDK | 当前版本、认证方式、能否复用本机授权、会话费用或限额不可预设 | [P04-01](https://github.com/OYLPY/stock-monitor/issues/33) 建真实 PoC；不以口头保证取代测试 |
| 数据获取 | 美日股实时/分钟级价量、JPX 接口授权与成本未获确认 | [P04-03](https://github.com/OYLPY/stock-monitor/issues/35) 按原始服务条款评估；无可信数据仅 Fixture |
| 市场日历 | 特别休市/临时早收盘需要可更新权威日历 | [P07-01](https://github.com/OYLPY/stock-monitor/issues/48) 设计版本化日历和覆写审计 |
| 回测可信度 | 样本外不足、未来函数、复权/成本/汇率偏差会误导策略评分 | P09 完成可重播回测及跨环境测试 |
| 风控实现 | 2%计划损失不等于真实市场最坏亏损；跳空可能突破止损 | [P01-03](https://github.com/OYLPY/stock-monitor/issues/22) 明确预计损失与尾部风险、审计口径 |
| 本地可用性 | 睡眠/关机、系统权限限制后台运行 | [P04-04](https://github.com/OYLPY/stock-monitor/issues/36)、P11 验证与文档披露 |
| 对抗性内容 | 新闻/财报/网页中的恶意指令可能污染 AI 研究 | AI 视外部材料为数据，权限/账本隔离，P08 与 P12 测试 |
| 成本 | Codex 和行情接口可能存在不可预知费用 | 默认不购买任何收费服务，缺权限 BLOCKED_EXTERNAL |
