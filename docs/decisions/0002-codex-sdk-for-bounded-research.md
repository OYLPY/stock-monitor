# ADR-0002：用 Codex SDK 执行有界的本地研究任务

- 状态：Accepted，受 P04-01 安全与授权 PoC 门禁约束
- 日期：2026-11-15
- 范围：P08 六职责研究任务的模型执行入口

## 背景

研究角色是一个后台研究任务内的串行职责步骤，不是 Codex 聊天产品。V1 无应用登录、用户管理或需要长期维持的 Codex 对话 UI。当前仓库的 `@openai/codex-sdk` 依赖用于开发执行器；这不代表产品侧模型调用已经实现。

官方文档将 TypeScript Codex SDK 描述为用于程序化任务、启动/继续/恢复本地线程并读取结构化事件的接口；SDK 当前实现包装本地 Codex CLI。App Server 则提供 JSON-RPC 客户端协议，面向需要在产品内提供认证接入、持久对话、审批、流式事件和中断控制的深度集成。它不是比 SDK 更安全的替代执行环境。

## 决策

P08 的有界、服务端后台研究步骤以 Codex SDK 为首选执行入口。每次调用只接收应用按任务组装的、带来源 ID 和时间状态的结构化证据；使用 Schema 输出并由应用再次校验。确定性服务维护任务状态、证据等级、风控裁决和账本权限。凭据/网络/模型调用错误按 `BLOCKED_EXTERNAL` 或实际失败原因记录，不回退为 Fixture 成功。

Codex 进程只由本机服务端或 Worker 调用，产品不连接浏览器到 Codex 进程。使用最小环境、隔离的工作目录及只读/更严格的执行策略；不挂载数据库、账本或秘密目录，不启用任意 shell、文件写入、外部网页搜索、MCP 或模型选定的任意 URL 请求。Codex 服务自身所需的出站连接与应用数据供应商访问是两个独立边界：只允许前者由 Codex 适配器发起，行情/披露获取由应用的受限只读数据适配器执行。若 SDK/CLI 无法在目标环境中可靠落实这些限制，P04-01 必须记录阻断并重新审议此 ADR；不得直接放宽权限或自动改用 App Server。

用户已有的本机 Codex CLI 授权（若 P04 确认可用）属于本机执行环境授权，不属于产品登录流程，也不得以产品账户或远端身份系统实现。无可用授权、额度或连接时，本地已保存资料仍可查看，AI 任务明确不可用。

SDK 文档说明 Codex 线程历史保存在本机 `~/.codex/sessions`。研究任务只向模型提供最小必要的公开证据和研究上下文；不得包含任何凭据。P04-01 还需核实目标 SDK/CLI 版本的实际会话持久化、目录权限和清理方式，再确定敏感研究内容是否可发送。

## 替代方案

| 方案                               | 取舍                                                                                                                                                                                               | 结论                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Codex SDK                          | 适合有界的程序化后台任务，支持结构化结果和流式进度；SDK 包装 CLI，需验证版本、安装、凭据继承、隔离及子进程退出语义。                                                                               | 首选，须经 P04-01 安全门禁                                             |
| Codex App Server                   | 有标准化的线程/回合 JSON-RPC 生命周期、审批请求和客户端事件，适合产品内的持续对话和人工确认体验；对当前无聊天/无 Codex 审批 UI 的 V1 增加协议、状态和维护面，也共享 Codex harness 的工具安全问题。 | 当前不选；若产品需要持久互动对话或 Codex 工具审批界面，再以新 ADR 评估 |
| 直接调用模型 API 并自建 Agent loop | 可减少 Codex CLI 工具能力，但要自行维护上下文、重试、事件和工具循环；可能与用户已选 Codex 技术方向重复。                                                                                           | V1 不选；若 SDK 无法满足安全门槛，先阻断和重新决策                     |
| 离线 Fixture                       | 可用于标明为 `DEMO_ONLY` 的演示和测试，不能替代真实模型研究结论。                                                                                                                                  | 仅隔离演示，不作为在线服务回退                                         |

## 失败处理与验收门槛

- 进程未安装、启动失败、凭据缺失/失效、限额或连接错误：记录有限且可分类的失败；身份、权限、费用问题不重试；不得展示伪造研究输出。
- 超时或取消：终止本次调用并保留失败/取消记录；不采纳延迟到达或无完整 Schema 的输出。
- 恶意来源文本：作为数据传递，不视为指令；其输出仍须通过 evidence ID、Schema、权限和确定性规则校验。
- P04-01 必须实测授权方式、成功/失败调用、Schema、超时/中断、日志脱敏与文件/网络权限；未验证项保持 BLOCKED 或 NOT_VERIFIED。
- 实际交易审批、资金计算、模拟成交或账本写入永不交给模型或 Codex 工具执行。
