# ADR-0003：由独立 Worker 执行本地计划任务

- 状态：Accepted
- 日期：2026-11-15
- 范围：V1 晨报、市场扫描、日审计和周审计任务的执行生命周期

## 背景

监控和报告必须在浏览器页面关闭时仍可运行；本机服务或设备停止、睡眠时则不能声称持续监控。任务有市场时段和来源时效要求，需要使用持久化状态恢复，避免重复报告或模拟副作用。

## 决策

计划任务由独立本地 Node Worker 进程调度和执行。Worker 与 Next.js 共用 SQLite 系统记录库，通过 Application 用例读写任务；持久队列记录计划时刻、认领、执行结果和失败原因。前端只提交用户请求、查询状态和显示结果，不用浏览器定时器负责业务调度。

Worker 进程与网页一起由本机启动入口管理；实现阶段使用 OS/数据库级单实例和持久任务认领，避免重复 Worker 同时执行。具体队列字段、租约、重试和唯一幂等键由 P03-05/P11 决定。只对明确可重试的暂时性故障有限重试；持久化更新与副作用必须按幂等业务用例处理，不能承诺跨网络的物理“恰好一次”。

## 替代方案

| 方案                              | 取舍                                                                                               | 结论    |
| --------------------------------- | -------------------------------------------------------------------------------------------------- | ------- |
| 浏览器 `setInterval` / 页面计时器 | 页面关闭后不运行；标签页节流、设备休眠也会打断或延迟。无法作为持续监控的调度器。                   | 拒绝    |
| Next.js 进程内计时器              | 浏览器关闭后可运行，但与 Web 服务生命周期绑定；服务重启会中断调度，后台任务与请求进程隔离不足。    | V1 不选 |
| 独立 Node Worker                  | 在浏览器退出时可独立运行，进度与任务状态可持久化；进程存活仍受机器睡眠、关机、退出和本地故障影响。 | 采用    |

## 生命周期与失败处理

- 启动时先确认数据目录和 Schema 可用，再让 Worker 认领任务；数据库失败时 Worker 不执行副作用，Web 明确显示本地存储不可用。
- 关闭浏览器不会停止 Worker。只有本机运行入口和 Worker 进程仍在运行，任务才可能继续。
- Windows/macOS/Linux 睡眠、关机或用户结束进程期间，任务不会执行。恢复后重新核对当前市场日历和数据时效：错过的盘中扫描记作 `SKIPPED` 并注明错过窗口，不补造实时事件；其他摘要是否可补跑由 P11 的具体任务合同决定。
- Worker 或宿主崩溃后，过期认领任务可被恢复流程重新评估。恢复必须以持久化任务 ID/幂等键避免重复结果；无法确认完成状态时标记失败/待恢复，不得推断为 `DONE`。
- 网络、Codex 或供应商不可用不影响本地已保存报告、历史资料及账本的读取；依赖外部的任务在有限超时后记录真实失败/`BLOCKED_EXTERNAL`，必要输入不足的结论为 `NOT_VERIFIED`。Fixture 只在显式演示/测试流程中使用并标为 `DEMO_ONLY`。
- 若系统时间跳变或交易日历不可用，暂停依赖时段的扫描并记录原因；不以本机时钟推断未验证的市场状态。

## 后续验证

P03-05 定义任务 Schema、时区/计划实例、唯一性、租约、恢复和重试；P04-04 验证浏览器关闭、Worker 生命周期、PC 睡眠/恢复和重复执行；P11 实现调度与市场窗口，P12 演练崩溃和恢复。本 ADR 不表示 Worker、调度器或 OS 自启动能力已实现。
