## 设计目标与不变量

1. 每条研究事实、行情观察、事件或日历项都可追溯到来源记录和采集时间；缺少来源或时间时保留缺口，不填默认值。
2. 原始来源记录和规范化观察分开保存。更正、撤回、重新发布或解析器修正产生新的证据/修订关系，不覆写已经用于报告的证据快照。
3. 来源可靠性是“此来源对这类事实的权威角色及依据”，不是由知名度、标题或来源数量推导出的全局数字分数。不同字段可有不同的权威来源。
4. 数据实际来自网络不代表它实时、完整、准确或获准用于本产品。不得将 `REAL` 等同于实时，也不得将结构化格式等同于核实完成。
5. 所有事实、假设与推论引用稳定的 `evidenceId` / `sourceId`。新闻转载可帮助发现事件，不能单独升级为官方事实或无来源信号。
6. 供应商未选择、条款/许可未核实、凭据缺失或数据无法取得时，按来源不可用/未验证处理；不以 Fixture、缓存旧值或空结果伪装实时成功。

## 来源注册与适配器边界

每个适配器在来源注册表中声明其 `sourceId`、发布方、适用市场/证券类型、可提供的数据类别、来源角色、文档/接口版本、引用 URL、访问方式、许可依据、凭据要求、已知覆盖范围、更新时间语义、声明延迟、请求限制、历史范围和更正/撤回行为。未核实的能力标为未知，不能对上层宣称实时或完整覆盖。

适配器只负责获取来源记录、保留原始标识/时间/响应元数据、校验格式并产出规范化候选。它不决定事实是否 VERIFIED，不静默选择冲突值，不生成投资信号、风险通过或模拟成交。应用层按具体工作流定义必需来源，并使用下文状态门禁。

### P07-04 官方宏观来源

- SEC、BOJ、BLS 与 Fed RSS 采集器在 `src/providers/disclosures/collectors.ts`。公开来源单次请求失败、响应 schema/覆盖不匹配、响应截断、响应超限或非官方链接时，不写入引用并返回 `NOT_VERIFIED`；成功只说明该次接口响应被验证，不代表实时性或完整覆盖。
- SEC Submissions 使用零填充 CIK 与显式联系 `User-Agent`，SQLite 审计链限每个本地数据库滚动 1 秒最多 10 次。只把 accession、申报日期和 form 建成引用；`filingDate` 保持原始日期文本，`publishedAt` / `availableAt` 不从接受或采集时刻推导。官方网页没有列出 Submissions JSON 的完整字段 schema，因此真实响应字段仍须运行时验证。
- BOJ `getDataCode` 最多查询 250 个系列、60,000 个观察；采集器每个本地数据库每秒最多请求一次，任何非空 `NEXTPOSITION` 或返回系列/日期数组不完整都整体降为 `NOT_VERIFIED`。`SURVEY_DATES` 是观察期；`DATE` 是输出文件生成时刻，`LAST_UPDATE` 是最近修改日，两者都不替代发布时间。
- BLS v1 每次最多 25 个 series、10 年，未注册使用者每滚动 24 小时最多 25 个查询；采集器持久记录尝试次数。返回标记 `DELAYED`，观测期仅保留为 `rawTimeText`，没有发布日期时保持 null。Fed 与 BOJ RSS 必须是官方 HTTPS URL、禁止跨域重定向和 DTD，并按本地规则每分钟最多一次需求驱动查询。P11-06 报告任务也取 BOJ `FM08` 的 `FXERD04/FXERD05`；观察日期标为 `Asia/Tokyo`，空值及当前东京日期与未来的日值不会进入 sourceRecord，避免把未完成时段当成最新已完成观察。
- EDINET/BEA 需要缺失的 API key，TDnet 需要未授权付费订阅，issuer IR 需逐站确认许可；这些来源不得由采集器绕过 `BLOCKED_EXTERNAL` 或手工引用边界。采集器不保存完整 HTTP/RSS 原文；RSS 与披露保存标题、链接、时间及内容 hash，BLS/BOJ 宏观序列保存观测期/数值摘要及 hash。该实现提供引用与变更识别，不构成获准的美日股票 OHLCV、完整经济日历或可用于策略回测的完整历史数据库。
- 源 ID 在同一 source 下用于幂等去重；同一 ID 的内容变化创建显式 supersedes 版本。多个不同 source 的同一语义事件归并留给 P07-05。

### P11-06 报告任务来源采集（2026-11-19）

- MORNING、DAILY_AUDIT 和 WEEKLY 报告开始分析前，请求 BLS v1 CPI-U/失业率、BOJ FM08 USD/JPY reference-rate series、Federal Reserve press-release RSS 与 BOJ official RSS。采集只使用公开端点，无 API key、账号或付费操作；当前 BOJ/RSS licenseStatus 仍为 UNKNOWN，成功访问不意味着获准转售或外部再分发。
- BLS 实测响应使用 `Results.series` 对象结构，series 项可带 `latest`；`footnotes` 可含空对象。采集器接纳这种结构，只持久化可解析的数值字符串，`-` 等 unavailable values 不当作观测数值；CPI/就业仍按 BLS 声明标为 `DELAYED`。

- 采集状态与报告限制逐来源保留。HTTP/超时/schema/限流故障不产生事实引用；空 feed 不表示没有新事件。没有获许可且覆盖充分的 US/JP 股票 OHLCV 时，策略候选固定为零，回测、收益或盘中判断不得标为已验证。

### 时间和时效计算

- `collectedAt` 使用本机 UTC 时间记录本次成功读取；它只证明本机何时取得响应，不证明发布方何时公开，也不修正来源时钟错误。
- 对价格和 FX，计算可见数据年龄时以 `marketAsOf` 对照 `collectedAt`；同时保留供应商声明的 `DELAYED`。有采集时间但无行情时间，不能据此计算行情新鲜度。
- 来源清单/记录的更新时间（例如 EDINET 的 `processDateTime`）保存为 `sourceUpdatedAt`，不能替代文件提交时间、披露时间或实际可见时间。
- 对披露/新闻，来源时间优先采用来源给出的发布时间/接受时间；页面更新时间不能冒充事件发生时间。新闻报道时间不等于所述事件时间。
- 对财报数值，报告期截止日不是 filing publication time。对宏观日历，计划发布时间不是实际 release time。
- SLA 按“来源 × 数据类别 × 市场 × 用途”配置；P04/P07 未以实际来源和样本验证前没有默认 SLA，也不允许实时声明。超过已验证 SLA 使用现有 `STALE` / `DATA_STALE` 语义；无法判断时使用 `UNKNOWN` 并将相关事实降级。

## 状态、可靠性与来源冲突

沿用 [FR-Research 的状态契约](../requirements/FR_RESEARCH.md)；这些维度彼此独立，不新增通用 `OFFLINE` 或 `CONFLICTED` 状态码。

| 维度         | 现有值                                                                                                                          | 判断规则                                                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据状态     | `REAL`、`DELAYED`、`HISTORICAL`、`FIXTURE`、`NOT_VERIFIED`                                                                      | `REAL` 只说明来自实际来源；不表示及时/准确/完整。`DELAYED` 必须有来源声明。`HISTORICAL` 说明事实属于已过去的市场时段。`FIXTURE` 说明合成/演示输入。                 |
| 来源状态     | `AVAILABLE`、`DELAYED`、`STALE`、`UNAVAILABLE`、`UNKNOWN`                                                                       | 来源覆盖和当前质量；不代替任务或报告状态。凭据、网络、许可或配置缺失时为 unavailable/unknown 并保留原因。                                                           |
| 报告验证等级 | `VERIFIED`、`PARTIAL`、`NOT_VERIFIED`、`DEMO_ONLY`                                                                              | 必要证据完整且时间/主体映射可靠才可 `VERIFIED`；非核心缺口须 `PARTIAL` 并逐项披露；核心来源缺失、冲突或过期为 `NOT_VERIFIED`；任何 Fixture 派生结果为 `DEMO_ONLY`。 |
| 扫描业务结果 | `NEW_EVENTS`、`NO_NEW_EVENTS`、`SKIPPED_CLOSED`、`SOURCE_UNAVAILABLE`、`DATA_STALE`、`CALENDAR_UNAVAILABLE`、`PARTIAL_COVERAGE` | 只有日历与全部必需来源完整且在有效 SLA 内时，无新事件才可记 `NO_NEW_EVENTS`；未取得数据绝不等于空结果。                                                             |

来源角色/可靠性按每条来源事实分别判定：原始监管申报、交易所正式披露、发行人原始公告、官方机构结构化派生数据、获授权供应商数据、二手新闻/聚合内容、Fixture 或未知。记录角色依据、许可/授权验证和实际质量检查；角色不是投资建议、预测准确率或全局可信分数。来源角色未知时不升级为 VERIFIED。

处理多源冲突时：

1. 保留每个来源快照、原始标识、时间、取值和来源角色，不按“最新值”“多数票”自动覆盖。
2. 先确认主体/证券映射、币种/单位、报告期、市场时间和修订编号是否相同；只有可比口径才作为冲突候选。
3. 权威顺序按事实类型定义（例如监管申报事实回链申报文件、交易所成交时点回链获授权行情、公司自述回链发行人原文），不能有一个全局“最可信来源”替所有字段作决定。
4. 冲突未消解时保留问题说明并降为 `PARTIAL` / `PARTIAL_COVERAGE`；若冲突影响核心事实或风险输入，则 `NOT_VERIFIED`。不得自创状态码来掩盖缺口。

## 工作流门禁与降级行为

| 情况                                   | 允许行为                                                                               | 必须限制                                                                                                                                  |
| -------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 网络/凭据不可用                        | 展示本地已缓存资料；有有效历史区间时运行历史分析。                                     | 当前来源标 `UNAVAILABLE`/`UNKNOWN`；任务记录 `BLOCKED_EXTERNAL` 或失败原因；依赖缺失来源的结论 `NOT_VERIFIED`；不可输出“已确认无新事件”。 |
| 仅有合法历史行情                       | 用明确数据区间和复算规则做历史分析。                                                   | 数据标 `HISTORICAL`；不得作为当前报价、实时异常或新模拟成交。                                                                             |
| 仅有延时行情                           | 显示供应商声明的延迟和原始市场时间；仅在用途允许且 SLA 已验证时用于相应历史/延迟观察。 | `DELAYED` 不自动满足实时门槛；无授权或延迟声明时不使用为正式实时输入。                                                                    |
| 来源过期、缺时区/主体/币种、字段不完整 | 保留收到的值和缺失原因，列出未覆盖字段。                                               | 不能填零或猜映射；影响核心结论时 `NOT_VERIFIED`。                                                                                         |
| 多个来源冲突                           | 以证据链展示各版本并保留修订关系。                                                     | 不隐藏来源、不自动挑选最有利值；冲突未解时按上节降级。                                                                                    |
| 明确启用 Fixture                       | 在隔离的演示/测试流程运算。                                                            | 输入保留 `FIXTURE`，所有派生图表、报告、策略结果和评估标 `DEMO_ONLY`；不可合并真实/历史绩效或纸面账本。                                   |
| 来源日历不完整/无法更新                | 可以显示最近已取得的日程及其抓取时间。                                                 | 不把旧计划当作确认的未来时间；日历门禁失败时 `CALENDAR_UNAVAILABLE` 并停止相关扫描。                                                      |

实时信号、重大事件提醒和新模拟成交必须同时通过：来源覆盖符合该工作流要求；证券/市场/事件映射可核验；必要时间与币种/单位齐全；数据未超过经验证 SLA；供应商许可与延迟状态允许该用途；核心来源无未解决冲突。任一不满足就按上表降级。确定性交易风险、批准与账本规则仍归 [ARCHITECTURE.md](ARCHITECTURE.md) 的服务端纸面交易用例，不由适配器或 AI 代替。
