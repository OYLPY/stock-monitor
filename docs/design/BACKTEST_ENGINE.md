> 相关设计：[DB Schema](DB_SCHEMA.md)、[API/DTO 契约](API_CONTRACTS.md)、[数据溯源](DATA_PROVENANCE.md)、[风险引擎](RISK_ENGINE.md)。

## 决策边界

- 历史回测用于检验明示假设，不证明未来收益。策略只能按完整的样本外证据进入验证候选；上线后的前向验证先使用锁定版本的纸面测试，V1 不连接券商、不真实下单。
- 使用目标市场和策略所能取得的**最长合规、可复原、点时有效**历史，并披露起止、频率、覆盖缺口和证券池。没有统一的“必须几十年”门槛：年份更久不代表数据更完整，也不代表不同时期的市场结构可直接比较。
- 历史证券池必须还原当时可知的成员与退市证券；价格、公司行动、财报/事件、FX、市场日历、修订版本均须保留事实生效时间和当时可用时间。无法还原关键点时信息、退市结果或数据修订时，回测为 `NOT_VERIFIED`，不得用当前存续标的或事后信息补成历史事实。
- 只有有来源、有授权、可复算的历史数据可标为 `HISTORICAL`。Fixture 的全部派生结果标 `DEMO_ONLY`，不得混入真实历史绩效或纸面账本。
- 数据清单、策略/参数 hash、指标与调整规则、撮合和费用/FX 规则、市场日历、引擎版本及样本边界共同构成不可变运行输入。相同输入版本重放应给出相同结果；数据修订须创建新运行，不覆盖旧运行。

## 数据、时点与复权

每个 bar 至少记录证券、周期、开始/结束市场时间、交易所时区、OHLC、成交量及单位、币种、来源/版本、数据类别、可用时间、调整口径和质量状态。原始观测与推导的调整序列不能混为一个可执行价格序列。

- **点时资格：**信号仅能读取该信号时刻已经发布且可观察的数据。证券池、退市、公司行动和 FX 也遵循同一约束；事后修订另存版本并标明首次可用时间。
- **bar 可用时间：**已完成 bar 的信号时点是该 bar 数据实际可用时间，不能早于市场收盘；来源未提供可用时间时信号时点为空且结果为 `NOT_VERIFIED`。公司行动只有在生效且不晚于对应有效 bar 的数据可用时间已知时，才可重基指标历史。
- **拆股：**拆股比例按“新股数 / 原股数”记录为 r；在该行动已生效且当时已知后，连续指标可将行动前历史价格除以 r、成交量乘以 r。每个历史信号只应用当时已生效/可知的公司行动；若数据源的最新序列包含回测时点之后的拆股调整，必须按时点重建，不能直接当作点时数据。实际成交仍使用当时可交易的价格与股数。
- **现金分红：**交易信号默认使用拆股调整的价格；总回报序列只用于总回报比较，记录除息时点和再投资规则，不可作为订单撮合价格。现金账本按适用市场规则在支付时点记账；不得重复计入已含在总回报序列中的分红。
- **缺口与异常：**不插值 OHLCV、不将缺失 bar 当作零收益或零成交量；保留原缺口和原因。若缺口会改变信号、成交或关键指标，结果为 `NOT_VERIFIED`。市场休市依据该市场版本化日历，不按固定 UTC 偏移推算。
- 报告逐市场给出数据起止、bar 数、有效覆盖/缺口、证券池及退市覆盖、复权与修订版本。未经授权或缺少必要来源不扩写为“全市场几十年历史”。

## 指标定义

所有指标只使用参数/策略版本指定的**已完成 bar**，窗口长度属于冻结参数并随运行记录。窗口不足、输入缺失或单位不一致时返回缺失原因，不生成伪值。

| 指标         | 确定性定义                                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| MA(n)        | n 根已完成 bar 的收盘价算术平均；窗口及价格调整口径随策略参数固定。                                                                                                      |
| TR           | `max(high - low, abs(high - previousClose), abs(low - previousClose))`；首根缺少前收盘时不伪造 TR。                                                                      |
| ATR(14)      | 对 TR 使用 Wilder 平滑；首个值为连续 14 个有效 TR 的算术平均，之后 `ATR[t] = (13 × ATR[t-1] + TR[t]) / 14`。首根无 TR，至少 15 根连续 bar 才有 ATR。结果单位与价格相同。 |
| 日收益       | `C[t] / C[t-1] - 1`；首根、缺口后首根没有收益值。                                                                                                                        |
| 已实现波动率 | 最近 n 个有效收盘到收盘对数收益 `ln(C[t] / C[t-1])` 的样本标准差；报告窗口与每 bar 波动率。没有明确交易日历和年化因子时只提供未年化值。                                  |
| 收益分位数   | 最近 n 个有效对数收益的 P05/P50/P95，按 R-7 线性插值；缺口后重新累计窗口。                                                                                               |
| RSI(14)      | 最近 14 个有效收盘变化的 Wilder 平均涨幅/跌幅，按 `100 × avgGain / (avgGain + avgLoss)`；两者均为 0 时取 50，无跌幅取 100，无涨幅取 0。                                  |

计算保留项目规定的精确数值语义，不用 JavaScript `number` 处理资金/价格/FX。指标输出同时携带有效时间、调整口径和输入来源，便于复算。

## 信号和成交时间

- 日线信号在收盘 bar 完成且其数据已可用后计算，记录该数据可用时点，最早在下一可交易 bar/时点执行；禁止在产生信号的同一根 bar 收盘成交。
- 盘中策略只使用当时已完成的盘中 bar；由该 bar 产生的信号最早从下一可交易 bar/时点执行，不可在同一根 bar 的收盘成交。若策略依赖 bar 内先后顺序而 OHLCV 无法证明该顺序，按对策略不利的规则处理，或将该次成交及受影响结果标为 `NOT_VERIFIED`。不推断 bar 内路径，不补造报价。
- 若同一 OHLC bar 同时触发止损和止盈且无更细粒度数据，按 FR-Trade 既定规则止损优先，或标 `NOT_VERIFIED`；不选择更有利的触发顺序。
- 开盘跳空越过止损时，成交价不能优于可观察到的下一可执行价格；缺少足够粒度验证价格时，不宣称精确成交。停牌、涨跌幅限制、无成交、无报价、交易单位和现金约束均按市场规则处理，无法验证时不成交并披露。
- 收盘/开盘价只作为对应 bar 模型的历史代理，报告必须声明使用的是 bar 撮合而非逐笔/真实可成交报价。滑点、价差和成交限制由版本化成本规则给出，不得静默设为零。

## P09-03 初始策略

`generateInitialStrategySignals` 接受冻结的严格参数、证券交易单位、归一化 OHLCV 与限定到该证券且按点时记录的财报事件，返回可直接作为 `BacktestSignal[]` 交给 P09-02 引擎的多头信号；每个信号同时记录原因和来源记录。运行不搜索或自动优化参数，固定股数必须是交易单位的整数倍，每次最多维护一个策略仓位。

| 策略             | 入场                                                                                                                                                                        | 策略退出                                                                   |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 财报后漂移       | 完整且已核验的财报证据达到正向惊喜阈值；事件已可用后，在配置窗口内再观察到收盘价高于前一交易时段收盘价。事件与 bar 的可用时间相同则顺延到下一根可用 bar，避免猜测先后次序。 | 持仓时，达到负向惊喜阈值的已可用财报事件触发卖出；负向事件在空仓时不做空。 |
| 趋势/放量突破    | 已完成收盘高于前 N 根已完成 bar 的最高价，且成交量达到前 N 根平均成交量的冻结倍数。拆股将历史高价和成交量重基到当前 bar，并把行动来源写入信号。                             | 收盘低于前 N 根收盘均值。                                                  |
| 过度反应均值回归 | RSI(14) 不高于冻结的超卖阈值。RSI 来源记录覆盖最近缺口之后完整的指标输入历史。                                                                                              | RSI(14) 达到冻结的反弹阈值。                                               |

三类策略还共同使用 `stopLossBps` 单日收盘到收盘损失门槛，以及从入场信号起算的最大持有交易时段数。止损在完整 bar 可用后才发卖出信号，撮合仍由引擎在之后可用的时段开盘尝试；此 V1 的 `stopLossBps` 是单日收盘损失触发条件，不代表相对实际成交价的每笔最大损失保证，也不替代独立风控的单笔 2% 风险预算。样本缺口、未知可用时间、无完整复权覆盖或有效时点迟到的拆股会抑制受影响信号；持仓时数据不足会返回明确状态并生成保守退出信号。Fixture 派生信号只能标为 `DEMO_ONLY`，财报来源/覆盖缺失则不生成财报策略信号并标为 `NOT_VERIFIED`。

## P09-02 引擎 V1 执行规则

- 一次运行只接受一个市场、一个证券和一种报价币种；JP 仅使用 JPY，US 仅使用 USD。执行价格必须是未复权的实际开盘价，已复权 OHLC 不得作为成交价格输入。
- 信号需晚于来源 bar 收盘且不早于其 `availableAtMs`。订单只尝试在 `openAtMs > signalAtMs` 的第一条预期交易时段开盘撮合，不在生成信号的 bar 成交。开盘价必须带有恰等于 `openAtMs` 的可用时间；开盘 bar 缺失或该时间缺失/迟到时订单不成交、不顺延。
- 买卖均采用全额或全无：不做部分成交；同一交易时段所有成交共享一个累计成交量参与上限，超出订单拒绝。订单按信号时间、再按稳定的 ID 顺序处理。
- 每次运行须提供按有效日期排列、互不重叠的成本模型版本，覆盖回测中的每个交易时段；模型包括最小价格跳动、价差、每边滑点、按成交额比例费用、每股费用、固定最小货币单位费用和最大成交量参与比例。买入价向上、卖出价向下按 tick 取整；价差按半边、滑点按每边计入，比例费用按费用最小单位向上取整。模型缺失的日期不撮合并使运行保持 `NOT_VERIFIED`。
- 卖出产生未结算应收，不得用于同一开盘或结算时间之前的买入。结算须按成交日期提供带来源记录、版本和精确时间戳的规则；缺少规则的卖单不成交。引擎只在不早于该时间的开盘/收盘处理边界释放应收，不硬编码单一 T+ 天数。
- 持仓和现金使用整数股及货币最小单位。只允许多头、无借款；超出已结算现金、持仓、交易单位或累计成交量的订单全额拒绝。拆股只在 `knownAtMs < openAtMs` 时调整持仓和待成交订单；恰好在开盘时点或之后才获知的拆股停止后续撮合，并将权益标记缺失。现金分红按生效开盘前持仓计应收，依据明确的支付时间和预扣比例结算；不改写信号价格。
- 任何 Fixture 派生运行的 `resultClass` 为 `DEMO_ONLY`；其余来源、日历、公司行动、成本、开盘价时间或结算证据不足时为 `NOT_VERIFIED`。缺少下一时段行情、待处理拆股或结算规则不生成已验证绩效。
- 运行结果保留引擎版本、完整输入 hash、行情/证券/公司行动/日历/结算来源标识、实际使用的成本版本；每笔成交绑定开盘价来源记录与成本版本/来源记录，以便复算。

## 成本与收益口径

费用和撮合模型按市场、产品、币种、适用期版本化，并记录来源与 hash。应覆盖可适用的佣金、交易所/监管费用、税费、买卖价差、滑点、FX 兑换成本及交易单位；具体费率须经来源验证，不在此文档臆造默认数值。任何必要成本缺失时，`net` 收益、胜率和评分均为 `NOT_VERIFIED`。

成交逐笔保存时间、数量、价格、币种、模型版本和费用明细。账户现金/仓位演进与分红等公司行动使用 [风险引擎](RISK_ENGINE.md) 及账本契约；不得因卖出款未结算、外币购买力缺失或资金不足而假设可继续买入。

胜率按“净盈利已平仓交易数 / 全部已平仓交易数”计算，净损益已扣全部费用；平仓交易、未平仓浮动损益和零损益交易分别披露。至少同时报告交易数、盈利/亏损/持平数量、平均净盈利、平均净亏损、净期望、累计/年化净收益（仅当年化口径有效）、最大回撤、费用总额和执行假设。

```text
net expectancy per closed trade = (winning trades × average net win
                                  + losing trades × average net loss
                                  + breakeven trades × 0)
```

示例：胜率 90%，盈利单平均 `+1%`、亏损单平均 `-12%`，期望为 `0.9 × 1% + 0.1 × (-12%) = -0.3%`，尚未考虑成本。因此胜率只是描述性指标，不能作为策略赢家选择标准，也不能替代回撤、尾部损失、成交可行性或跨阶段稳定性。

## 样本划分、参数选择与前向验证

1. 每个研究候选和每次参数尝试写入试验清单：试验 ID/时间、策略代码与参数 hash、数据清单/区间、目标指标、样本角色、研究者选择动作和结果。失败与淘汰的尝试也保留，避免只看到胜出的配置。
2. 按时间先后划分训练、验证和测试窗口。参数只能依据当前测试折之前的数据选择，并在该折开始前冻结；每折记录参数 hash 和边界。walk-forward 后续折可以使用其时点之前已发生的数据重新训练，但必须事先固定滚动/扩展窗口及重训规则，每折参数版本单独记录；任何折不得使用自身测试窗口结果选参。
3. 留出最后一段从未参与选择的最终 holdout。查看最终 holdout 后，若据此改动策略，该 holdout 即不再是未触碰测试；必须产生新策略版本和新的前向数据，不能继续把旧 holdout 称为独立验证。
4. 对跨期持仓或标签重叠的策略，训练与测试边界之间须排除会泄漏未来收益的重叠区间；报告实际排除区间。不可实现无泄漏划分时，相关验证为 `NOT_VERIFIED`。
5. 仅在候选配置数和样本足以支持时，可附加 Probability of Backtest Overfitting (PBO/CSCV) 作为多次试验选择偏差诊断；必须给出全部尝试配置。它不能替代按时间向前的样本外验证，也不能作为一次新的调参机会。样本不足时明确不计算，不伪造结果。
6. 每个折和总览均报告样本内/外边界、交易数、净胜率、净期望、收益分布、回撤、成本、证券池和数据覆盖。若历史窗口没有足够的有效观察/独立交易、成本不可知或核心数据缺失，则评分缺项并标 `NOT_VERIFIED`，不把全历史样本内最优配置宣称为可投资赢家。
7. 参数冻结后的新数据可做前向纸面验证，版本和规则不得因前向结果而静默变化。任何参数更改都开始新的试验记录。V1 前向验证不连接真实资金或下单接口。

历史样本长短须和策略频率、预期持有期、交易样本及市场制度一起解释。最老数据若采用不同制度/数据粒度，应分阶段报告，不因跨越更多年份而自动获得更高可信度。PBO 原始研究说明多配置择优会产生回测过拟合；股票数据漏掉退市结果也会带来系统偏差，见文末研究来源。

每项实际尝试都以不可变 `backtest_runs` 记录，包含研究试验组 ID、尝试 ID、参数 hash、样本角色、fold 边界、结果和状态；被淘汰、失败或不可执行的尝试也必须保留。按试验组可还原全部已尝试配置及选择过程。若试验清单不完整，不能计算完整的选择偏差诊断，也不能声称已完成无偏的“最佳策略”筛选。

### P09-04 Walk-forward 验证

`runWalkForwardValidation` 用严格递增的市场交易日构造 expanding 或 rolling 训练窗、隔离期（embargo）和固定长度测试窗。测试窗不得重叠；窗口不足时返回 `NOT_VERIFIED`，不调用参数选择器。每折参数选择器仅收到训练窗，必须返回本折全部尝试、训练期评分、唯一选中项和参数；系统在调用评估器前冻结参数并记录其 SHA-256、训练数据 hash、测试数据 hash 与完整输入 hash。每折同时记录实际回测引擎版本。后续折可把已经发生的测试数据纳入新的训练窗，但每折必须重新记录选择及参数版本。选择器代码不得通过外部闭包或全局状态读取本折测试数据；函数参数隔离不能替代对选择器实现的审查。

评估器只能把测试窗内的已平仓交易交给报告，并声明底层回测的 `VERIFIED`、`NOT_VERIFIED` 或 `DEMO_ONLY` 状态；未平仓数量必须单独报告。净收益是扣完已声明费用后的每笔收益（bps）。每折报告交易数、净胜/负/持平数、胜率、净收益均值与 P05/P50/P95。每折至少 30 笔已平仓样本才可能标记 `VERIFIED`；少于 30 笔或测试末仍有未平仓仓位标记 `NOT_VERIFIED`。30 笔只是软件最低门槛，不构成统计充分性证明，也不表示收益为正或策略可投资。

重采样使用预先固定区块长度的 circular block bootstrap，每折 1,000 次，报告平均净收益的 95% 百分位区间；区块长度必须小于该折交易数，否则不给区间并标记 `NOT_VERIFIED`。交易按退出日期排序，区块保留相邻交易顺序。收益分布分位数采用升序样本上的线性插值。不同折可能使用不同参数，因此总览合并的交易分布仅作描述，不把各折不同参数的收益拼成一个 bootstrap 区间。区间只表达该重采样方法下的不确定性，不能消除制度切换、退市偏差、选择偏差或区块长度假设。Fixture 结果始终为 `DEMO_ONLY`；没有可信数据或完整已平仓证据时保持 `NOT_VERIFIED`。

此任务生成可哈希、可重算的内存报告，不负责写入 `backtest_runs`；数据库持久化及从本地历史来源到策略、回测和报告页面的完整接线留给 P12-04。

V1 单次输入上限为 100,000 个交易时段、500 折、每折 1,000 项参数尝试；超限时拒绝运行，不截断数据或尝试记录。

## 2020/2022 压力与费用敏感性

- `runStressSensitivity` 在 `src/features/validation/stress-test.ts` 中对基线及显式场景重跑确定性回测，不读取网络或写入数据库。场景记录来源、版本、数据类别、验证状态、佣金/价差/滑点增量、跳空滑点准备金、可选成交量参与率上限和 FX 冲击，并按完整输入生成 SHA-256。
- `gapReserveBps` 是额外施加到每笔成交的逆向滑点准备金，不重造历史跳空价格路径；历史开盘价仍按回测输入中的实际 bar 处理。成交量参与率只允许维持或低于基线成本模型。
- 2020 与 2022 分别报告实际市场日期边界、费用、交易数、收益和最大回撤。只有窗口覆盖证据完整且边界与回测 sessions 一致、OHLCV 与回测均为 `HISTORICAL`/`VERIFIED`、session 无缺口、选参历史已知时才提供历史指标。否则窗口为 `NOT_VERIFIED`，指标为 `null`；Fixture 始终是 `DEMO_ONLY`，不能通过外部 coverage 记录晋级。
- 跨币种指标逐交易日转换权益。FX 必须逐日匹配币种和日期，且市场时间、可用时间及有效期不晚于/覆盖对应市场收盘；缺失、迟到或未核验的 FX 不做插值或前向填充，受影响窗口保持 `NOT_VERIFIED`。`terminalFxShockBps` 只在完成逐日换算后改变窗口终值，是终值反事实冲击，不代表观测到的历史 FX 变化。
- 报告通过 `executionChanged` 标出成本或容量场景是否改变订单状态、成交日期或成交数量。同一成交集合下，额外费用/逆向滑点不得改善净权益；若压力导致订单因资金或容量限制而变化，必须披露该变化，因为减少亏损交易可能令净权益上升，这不能被误报为成本单调效应。`parameterSelection` 同时说明该窗口是否参与选参；参与过的窗口不能称为独立压力外推。
- 仓库当前没有可核验的 2020/2022 历史行情与 FX 观察，因此当前实现不会生成真实历史压力绩效。接入本地历史来源和持久化仍由后续 P12-04 负责；本任务不接入外部行情/API/云服务。

## 五维评分契约

沿用 FR-Trade-012 的五维、每维 1–5 分，总分 25。评分规则本身必须具版本并由确定性代码按已核验的证据映射；AI 只能解释证据，不能生成分数或填补缺项。P03 不臆造数值阈值；具体各分档门槛由 P09-06 用可复算数据确定。

| 维度         | 最低证据                                                                   | 缺失时 |
| ------------ | -------------------------------------------------------------------------- | ------ |
| 样本外稳定性 | 每折日期、冻结参数、净收益/分布、交易数及跨折变化                          | 不评分 |
| 扣费后收益   | 成本完整且可复算的净收益序列、费用明细；如展示基准，记录基准定义和计算口径 | 不评分 |
| 最大回撤     | 按逐时点可复算权益曲线计算的峰值和谷值、窗口边界                           | 不评分 |
| 成交可行性   | 交易单位、时间/价格粒度、流动性与成交限制、滑点和未成交处理                | 不评分 |
| 跨环境稳健性 | 市场/时期分组及每组可比的数据质量、交易数、净结果                          | 不评分 |

只有五维均有有效证据时才能显示完整总分；缺一维时总分为缺失，不能用剩余分数折算成 25 分。`>=18/25` 只表示“验证候选”，不能绕过独立风控、本地计划批准或其他系统门禁，也不等于自动投资许可。若评分规则或数据为 Fixture，结果只能是 `DEMO_ONLY`。

## 状态和输出

| 验证级别       | 回测输出规则                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| `VERIFIED`     | 关键数据、点时资格、证券池、费用/FX、撮合、划分及结果证据均完整；只表示本次历史/前向计算可复核，不代表未来保证。 |
| `PARTIAL`      | 非关键覆盖缺口逐项披露，受影响指标/区间明确标缺失；不得把局部结果表述为全市场/全期结论。                         |
| `NOT_VERIFIED` | 核心证据缺失、冲突、过期、授权不明、样本不足或无法消除未来信息；不产生已验证的胜率、净收益、评分或策略优胜结论。 |
| `DEMO_ONLY`    | 任一 Fixture 派生结果；仅验证流程/展示，禁止并入实证结果或纸面账本。                                             |

运行状态、数据类别和验证级别分字段保存，遵循 [数据溯源状态](DATA_PROVENANCE.md)；不得自创状态码。运行摘要至少包含试验清单引用、输入 hash、数据范围/缺口、策略与参数版本、每折和压力结果、全部指标、成本假设、分数/缺项原因及验证级别。

## 手算验收样例

| 场景                                                 | 预期结果                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------- |
| 日线收盘产生信号，同一日 OHLC 也出现止盈价           | 同日收盘不得成交；只能按下一可交易 bar 规则评估。          |
| 一根日线的高低同时跨过止盈与止损，且没有更细粒度数据 | 止损优先或该交易 `NOT_VERIFIED`；不得挑有利顺序。          |
| 某股票策略只含期末仍存续证券，且历史退市成员无法还原 | `NOT_VERIFIED`；不能声称覆盖全市场历史。                   |
| 历史行情几十年但公司行动/当时可用时间缺失            | 受影响策略 `NOT_VERIFIED`；时间跨度本身不能补齐证据。      |
| 样本外只有少量有效交易或试验只保留胜出参数           | 不完成评分；披露样本不足/选择记录不足并标 `NOT_VERIFIED`。 |
| 五维均有分数且总分 18/25                             | 只显示“验证候选”；无自动批准、建仓或真实投资动作。         |
| 90% 净胜率、平均盈利 1%、平均亏损 12%                | 净期望为 `-0.3%`（成本前示例），不得因胜率高而优先选中。   |
| 2020/2022 缺少合规历史数据                           | 对该压力窗口标 `NOT_VERIFIED`；不得用 Fixture 冒充。       |

## 研究来源

- Bailey, Borwein, López de Prado & Zhu, [The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)：多配置反复择优会使普通样本外表现也可能误导；PBO/CSCV 用作对选择偏差的诊断。
- Shumway, [The Delisting Bias in CRSP Data](https://www.tylergshumway.org/Shumway-DelistingBiasCRSP-1997.pdf)：退市收益缺失会使股票收益样本产生偏差，因此历史样本要处理退市证券和退市结果。

以上来源支持偏差控制原则，不替代本项目数据源授权、质量与覆盖的实际核验。
