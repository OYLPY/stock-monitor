# 本机启动、后台运行与故障恢复

> Doc ID: DOC-0014 · 目录：[DOCUMENT_INDEX](../pmo/DOCUMENT_INDEX.md)

> 状态：P02-04 设计基线。以下行为是后续实现契约，不表示 Worker、数据库、数据源或 Codex 已接入。任务状态和步骤恢复契约见 [SCHEDULER.md](SCHEDULER.md) 与 [WORKFLOW_STATE.md](WORKFLOW_STATE.md)；实现及故障演练由 P04/P05/P11/P12 完成。

## 运行假设

- 本机启动入口运行 Next.js 服务与独立 Node Worker；服务默认只绑定 `127.0.0.1`。
- Worker 从 SQLite 中取得持久任务并调用服务端应用用例。浏览器只发起用户命令、查询进度和显示结果，不负责计划任务。
- `PENDING`、`RUNNING`、`DONE`、`FAILED`、`BLOCKED_EXTERNAL`、`SKIPPED` 是任务状态；报告/行情状态如 `PARTIAL`、`NOT_VERIFIED`、`HISTORICAL`、`DEMO_ONLY` 与任务状态分别保存和解释。
- 机器睡眠、关机、Worker 退出、本地磁盘或 OS 账户故障会中断任务。产品不承诺持续在线或系统级自动唤醒。

## 启动顺序

1. 启动入口解析本机数据目录，检查其读写权限，并启动 Next.js 与 Worker；不接受远端监听或开放隧道。
2. 服务端检查 SQLite 文件、Schema 版本和基础可读性。迁移与恢复属于受控生命周期步骤，不允许自动清空或用空库覆盖现有文件。
3. Worker 取得唯一实例/任务认领权后读取到期 `PENDING` 和过期 lease 的 `RUNNING` 任务，再按 [WORKFLOW_STATE.md](WORKFLOW_STATE.md) 检查已提交步骤、fencing generation、市场时段、来源状态和时效。
4. 若数据库损坏、迁移失败、磁盘不可写或实例锁冲突，阻止依赖该状态的写入/执行，保留原始文件并显示可定位错误。页面壳层仍可呈现本地存储不可用状态。

数据库基础连接不可用时，应用不能伪造余额、持仓、成功扫描或“没有新事件”。对模型和行情服务的连接失败不阻止本地已存资料与账本读取。

## 失效场景

| 场景                                                     | 可观测结果与处理                                                                                                                                                  | 禁止行为 / 后续验证                                                                                                        |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 浏览器标签页或浏览器关闭，Web/Worker 仍运行              | Worker 继续处理已持久化且到期的任务；重新打开页面查询同一任务记录。                                                                                               | 前端定时器不能接管任务；P04-04 / AC-NFR-007 实测。                                                                         |
| 机器睡眠、关机、用户退出 Worker 或本机重启               | 中止期间没有扫描。唤醒后校验市场时间、交易日历和数据新鲜度；错过的盘中扫描记为 `SKIPPED` 并带 `MISSED_WINDOW` 原因，只安排下一个未来窗口。                        | 不回放旧窗口并将其伪装为实时监控；更长摘要任务的有限补跑策略由 P11 决定；P04-04 / P12-05 实测。                            |
| Worker 在任务中崩溃                                      | `RUNNING` 任务按已提交 step checkpoint 恢复；未提交步骤沿用同一输入与幂等 ID 有限重试，失去 lease 的旧 Worker 不能提交。                                          | 不把崩溃状态标为 `DONE`；不声称物理 exactly-once。通知决策和任务完成同事务提交；P05/P11/P12-02 验证。                      |
| Web 与 Worker 启动了多个实例                             | 仅单个 Worker 获得执行权；数据库级唯一任务键/认领事务防止并发重复处理。                                                                                           | 锁冲突不能通过删锁文件或重置数据库强行继续；P03-05/P11/P12-02 验证。                                                       |
| SQLite 忙锁、只读、损坏、空间不足或 Schema 不兼容        | 明确记录数据库错误；短事务竞争按有限期限处理；超时或损坏时停止写入与纸面副作用。通过一致性备份在临时目标校验后恢复。                                              | 不回退到内存账本、IndexedDB 或空数据库；不宣称未验证的 RPO/恢复时间；P04-02/P05/P12-02/P12-05 验证。                       |
| 外部网络中断或 Codex 无凭据/额度/服务                    | 本地页面和已存材料仍可用。外部调用按请求期限失败；瞬时错误每任务最多总计 3 次，凭据、授权、费用和权限问题不自动重试；显式 resume 使用原输入并消耗同一总尝试预算。 | 缺少来源或模型结果时标为失败/`BLOCKED_EXTERNAL`、`NOT_VERIFIED`；不将 Fixture 或空列表当作真实结果；P04/P07/P08/P12 验证。 |
| 数据源返回旧、缺失、冲突或格式错误内容                   | 保存实际来源状态与失败原因；只保留仍满足输入要求的部分，相关报告降为 `PARTIAL` / `NOT_VERIFIED`。                                                                 | 不把旧报价当当前价、不把未获取解释成无事件、不允许模型补猜；P02-02/P07/P08/P12 验证。                                      |
| Codex 超时、退出码失败、输出 Schema/证据引用无效或被取消 | 结束并记录此调用真实状态；只接受完整、校验通过的结构化输出；取消后不采纳迟到结果。                                                                                | 不允许模型自行宣称修复或升级验证状态；P04-01/P08-05/P12-05 验证。                                                          |
| 系统时间跳变或市场日历不可用                             | 暂停依赖时间窗口的调度；标明本机时钟/日历不可用并等待校正或恢复。                                                                                                 | 不用本机时钟伪造交易所状态或推算事件发布时间；P07/P11/P12 验证。                                                           |
| 备份损坏/Schema 版本不兼容                               | 在临时位置检查校验摘要、应用版本和 Schema；失败时保留原数据库和备份并报告原因。                                                                                   | 不覆盖现有库或声称恢复成功；P05-05/P12-05 验证。                                                                           |

## 恢复不变量

1. 只有持久化提交成功的任务输入和账本事件才可作为后续事实；不能从模型、UI 内存或日志推断已提交。
2. 外部调用期间不保持 SQLite 写事务。来源证据/事件 revision/水位同事务提交；通知决策、通知唯一记录、最终步骤和任务完成同事务提交。外部供应商请求用幂等键/审计记录，不承诺远端调用 exactly-once。
3. 每次重启重新读取持久状态，不凭上一次 UI 进度恢复；重新验证 Git/代码仅适用于开发执行器，不替代产品任务状态。
4. 恢复后显示真实中断时间、失败原因、来源覆盖和采集/市场时间。没有数据不能被转换成“无事件”或“无持仓”。
5. Fixture 只在用户明确选择的隔离演示/测试路径内运行，派生内容全程保留 `DEMO_ONLY`，不进入正式纸面账本。
