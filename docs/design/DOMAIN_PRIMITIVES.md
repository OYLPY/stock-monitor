# 时间、金额、货币与市场标识原语

> Doc ID: DOC-0038 · 目录：[DOCUMENT_INDEX](../pmo/DOCUMENT_INDEX.md)

## 状态与依据

本契约细化 P03-02 的 API/DTO 约定、DOC-0013 的存储模型和 DOC-0015 的风险舍入要求。P05-02 将其实现为本地纯函数；交易日历、行情来源和交易逻辑仍由后续工作项负责。

## 目标与非目标

- 为日美市场模块提供同一套时区、精确金额、FX 方向和证券复合标识规则。
- 同一输入在同一运行时环境下可复算；金融计算不经过 JavaScript 浮点数。
- 本契约不判定交易所是否开市、不提供节假日日历、不采集数据、不保存行情，也不创建订单或成交。

## 时间与市场日期

| 市场 | IANA 时区        |
| ---- | ---------------- |
| JP   | Asia/Tokyo       |
| US   | America/New_York |

- 绝对时刻使用 UTC Unix 毫秒整数。市场时刻由绝对时刻和显式市场代码映射到对应 IANA 时区；不读取机器本地时区。
- 转换结果保留原绝对时刻、市场代码、IANA 时区、市场当地 ISO 日期、当地钟点和毫秒。纽约秋季重复小时会出现相同当地钟点，因此原绝对时刻不可丢弃。
- 市场当地日期是时区映射后的民用日期，不表示开市、交易时段或已完成交易日。交易日、假日、提前收市和午休由 P07-01 的版本化市场日历决定。
- 原始时间字符串如需转成绝对时刻，必须包含可解析的 UTC offset；没有 offset 的本地时间不由此模块猜测。保留来源原文和精度遵循 DOC-0012。
- IANA 规则来自 Node.js Intl/ICU 运行时数据。运行时升级可能更新历史或未来的时区规则；影响交易窗口的规则必须由版本化市场日历管理。

## 金额、定点数与 FX

- V1 货币只支持 JPY 和 USD；最小货币单位小数位分别为 0 和 2。金额以 BigInt 最小单位保存，价格和汇率以 BigInt 尾数及 scale 保存。
- 定点数输入必须是普通十进制字符串，不接受指数记法；支持的 scale 为 0–8。不能先转换为 JavaScript number 再做金融运算。
- 需要舍入的操作必须显式指定一种规则：
  - CEIL：向正无穷取整。
  - FLOOR：向负无穷取整。
  - HALF_AWAY_FROM_ZERO：最接近整数；正负半数均远离零。
- 风险损失折算到 JPY 使用 CEIL；风险预算使用 FLOOR。其他金额转换也必须由调用方显式选择适用规则，不得使用隐藏默认值。
- 汇率明确包含 baseCurrency、quoteCurrency、正数 mantissa 和 scale；数值单位定义为每 1 单位 base 币种可兑换的 quote 币种数量。例如 USD/JPY 的 150.25 表示 1 USD = 150.25 JPY。换算必须与输入金额的币种匹配；不自动求倒数。
- USD 100 minor units 按 USD/JPY 150.25 换算为 JPY 时，CEIL 得 151 JPY，FLOOR 得 150 JPY。JPY 123.1 的舍入结果为 CEIL 124 JPY、FLOOR 123 JPY；USD 12.345 使用 HALF_AWAY_FROM_ZERO 得 1235 cents。

## 证券复合标识

- 外部证券标识由 market、exchangeCode 和 symbol 三部分组成；复合键按这三个字段组成无歧义 tuple。
- exchangeCode 和 symbol 去除首尾空格并转成大写；空值和控制字符拒绝。不同交易所的相同 symbol 必须生成不同键。
- 复合键用于本地查找和去重，不替代稳定的证券实体 UUID。供应商代码、交易所、市场和有效期映射仍按 DOC-0013 与 DOC-0012 保存；不得把 ticker 当作全球唯一标识。

## 接口与失败行为

- 时间函数接收安全整数 UTC 毫秒和受支持的市场代码，返回包含时区上下文的当地日期/时间；非法时间或未知市场抛出可定位错误。
- 金额解析、FX 构造与换算只接收有界 scale、支持的货币和显式舍入方式；精度超界、非正汇率、同币种 FX 或基础币种不匹配均拒绝。
- 复合证券键拒绝空白标识和控制字符；不修补缺失字段，不推测市场或交易所。
- 所有函数在本地计算，不访问网络、不需要凭据或行情。上层 API 将在 P05-03 负责把领域错误转换为稳定 HTTP/DTO 错误码。

## 安全、权限与持久化

原语模块不读取数据库、环境变量、外部服务或用户凭据，也不执行账本写入。任何金额或标识持久化仍须经过对应 repository 和 SQLite 约束；研究模型不能直接调用数据库。

## 手算验收

- 2026-03-08T06:30:00Z 转为纽约时间 01:30；同日 07:30Z 转为 03:30，正确跨过春季 DST 缺失钟点。
- 2026-11-01T05:30:00Z 与 06:30:00Z 均显示纽约当地 01:30，但原绝对时刻不同。
- 2026-01-01T01:00:00Z 在纽约映射到 2025-12-31，在东京仍映射到 2026-01-01；这只是当地日期，不代表交易日。
- 同一市场和交易所的同一代码忽略大小写及首尾空格；不同市场或交易所生成不同复合键。
