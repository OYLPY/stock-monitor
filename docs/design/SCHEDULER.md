## 运行边界

- 独立本地 Worker 负责定时触发；浏览器关闭时 Worker 仍可运行。UI 手动启动与计划任务走同一应用服务、交易日历门禁、来源质量检查和幂等执行路径。V1 不引入远程队列、云端通知或产品用户/设备模型。
- Worker 在同一 SQLite 文件上工作；一次只有一个本地 Worker 取得执行权。外部网络调用不得持有 SQLite 写事务。数据、日历和权限条件不明时失败关闭。
- 扫描频率按已验证来源的 SLA、请求限制和任务类别版本化。没有经验证的来源或有效频率时，不启动伪实时扫描，也不在文档中承诺固定轮询间隔。

## 市场时间与触发窗口

交易时段使用版本化官方市场日历；判定结果携带交易所、本地业务日、IANA 时区、会话 UTC 边界、午休/提前收盘/临时休市状态和来源版本。Worker 写入任务记录时必须保存被引用的日历版本与市场时段。美股 NYSE 与 Nasdaq 分别判定；TSE 使用东京市场日历。具体规则承接 [FR-Research 的日历来源与窗口](../requirements/FR_RESEARCH.md#fr-research-001--002--交易日历与监测窗口)，不得硬编码 EST/固定 UTC 偏移或用开发机时区替代。

- NYSE/Nasdaq 核心时段为 09:30–16:00 ET；TSE 为 09:00–11:30、12:30–15:30 JST。窗口是左闭右开，盘前、盘后、期权及衍生品时段不纳入本 V1 股票日历。
- NYSE 提前收市日为 2026-11-27、2026-12-24、2027-11-26、2028-07-03、2028-11-24，收市时刻 13:00 ET；Nasdaq 2026-11-27、2026-12-24 收市于 13:00 ET。TSE 假日采用其现金股票市场日历，包含法定假日及 1 月 1–3 日、12 月 31 日休市。
- Nasdaq 官方页面目前只列出 2026 年；超出已核验年份（例如 Nasdaq 2027）返回 `CALENDAR_UNAVAILABLE / UNSUPPORTED_YEAR`。其他交易所超出各自覆盖年份时同样失败关闭，不从周末、美国联邦假日或相邻年份推导交易所假日。
- 临时休市覆盖必须携带理由、交易所官方 HTTPS 来源、来源版本和带时区的核查时刻；仅接受对应交易所的官方域名。单个有效覆盖优先于常规日历并在结果中回传来源信息；无效、重复或冲突覆盖返回 `CALENDAR_UNAVAILABLE`。
- 日历快照是静态数据。来源规则变化时应通过 Issue 更新快照、版本和验证样本；Worker 集成时还须将被引用的日历版本、市场日期及 UTC 会话边界写入任务记录。该解析器没有提供数十年历史交易日历，历史回测不能把当前快照当作完整历史日历。

- 会话窗口按左闭右开 `[open, close)`；边界由当地日历转换成 UTC instant。DST 切换不改变当地开收市定义；每次运行记录被引用的日历版本。
- 证券异常扫描只覆盖其上市市场当前开放的常规交易时段。TSE 午休/休市不扫描 TSE 证券；若美股同时开市，可单独扫描美股证券。盘前、盘后和未经批准的延长时段不属于 V1。
- 周末、整日休市、午休或提前收盘后没有适用市场时，任务状态为 `SKIPPED`、原因 `SKIPPED_CLOSED`；不创建成功扫描记录、不发“无新事件”通知、不推进来源水位。
- 日历缺失、过期或来源不可达时，扫描结果为 `CALENDAR_UNAVAILABLE`，任务记 `BLOCKED_EXTERNAL`；本地日历结构损坏或版本冲突时记 `FAILED`。两者都失败关闭，绝不假定开市或报告平静。
- Worker/设备离线错过的实时窗口记为 `SKIPPED`，原因说明 `MISSED_WINDOW` 和实际中断区间；恢复后不把过去窗口补跑并伪装成实时监控。日/周研究任务如按策略补执行，报告 `asOf` 使用实际执行时刻并明确延迟，不能沿用错过时刻。
- 会话窗口的扫描节拍、日/周任务时刻和来源集合是具版本计划输入；节拍必须满足已验证来源限制。无该项依据时阻断实时计划，不猜一个通用默认值。

## 任务唯一性与认领

计划任务幂等键为规范化输入的 SHA-256，至少包括任务类型、计划版本、目标市场/证券范围 hash、计划窗口 UTC 起止、当地市场日、日历版本和规则/config 版本。规范化输入以字段稳定排序的 canonical JSON 编码。DST 回拨产生的两个实际 UTC 窗口因此不会碰撞。相同计划槽位重复触发只对应一条 `task_runs` 记录；新计划版本、新槽位或不同范围生成不同键。

手动命令使用 API 规定的 UUIDv4 `Idempotency-Key`：相同键、相同规范化输入重放原任务；相同键、不同输入返回 `409 IDEMPOTENCY_KEY_REUSED`。重试沿用原任务和原幂等键，不创建看似新的扫描。

Worker 先取得本机单实例执行锁，再用短事务原子认领到期的 `PENDING` 任务并设置 owner/lease。认领必须受唯一幂等键和当前状态约束；锁冲突不得通过删除数据库、任务或锁文件绕过。租约超时后先按 [恢复协议](WORKFLOW_STATE.md) 核验检查点和副作用，再决定续跑。

## 成功水位与来源完整度

扫描水位按 `source × market × event category × scope/config version` 分别保存。来源给出可用游标时保存游标；否则保存该来源、该范围的最后成功可见时间及运行引用。不得用“本机当前时间”冒充来源数据覆盖水位。

- 一个来源只有在本轮该来源所需页面/区间完整读取、时间/主体结构校验通过，且记录与事件证据已持久化后，才推进自己的成功水位；这些记录与水位在同一 SQLite 事务提交。
- 来源证据、事件/修订、该来源水位和来源步骤检查点作为一个短事务提交。通知决策可能在后续步骤才完成；未决重大事件必须作为可检索的 pending 候选保留，后续任务从未决候选和当前成功水位之后的数据共同恢复。不能只从水位之后读取新数据，否则进程在水位提交后崩溃会永久漏掉通知。
- 任务失败、超时、取消、分页不完整或核心字段校验失败时，不推进受影响来源的水位。其他来源若完整，可分别提交；失败来源保留旧水位并显示真实来源状态。
- `NO_NEW_EVENTS` 仅当所有必需来源覆盖完整、数据在已验证 SLA 内、事件/行情身份可核验且没有新重大项时返回。无网络、缺凭据、Provider 未配置或数据过期时应报告 `SOURCE_UNAVAILABLE` / `DATA_STALE` / `PARTIAL_COVERAGE` 及 `NOT_VERIFIED`，不能等同于无事件。
- 迟到发现以来源首次可用/发生时间与成功水位比较，标记 `LATE_DISCOVERY`。过期项不补发为实时提醒；没有经来源样本验证的 SLA 时，不声称实时新鲜度。

## 事件身份、去重与修订

去重规则按版本确定，事件与证据分开保存。识别顺序如下：

1. 优先使用来源稳定事件 ID；同一来源事件的更新作为同一事件的新修订，不创建一条新的通知事件。
2. 没有稳定 ID 时，只移除来源适配器已确认的跟踪参数，保留未知 URL 参数；标题用 Unicode NFKC、大小写折叠和空白规范化，保留数字及可能有意义的标点。结合受影响证券/发行人稳定 ID、事件类别、可核验的发生/发布时点及结构化关键事实生成候选 SHA-256 指纹。算法和规则版本、原始来源记录都保留；指纹相同本身不能授权跨来源合并。
3. 跨来源只有在稳定事件身份或实体、类别、时点和关键事实足以确认同一事实时才归入同一事件簇。不能只因证券代码相同、标题相似或发布时间接近而合并；无法确认的候选保留为独立证据，不可静默压掉。
4. 标题改写/转载若可归入已有事件簇，只追加来源证据并保持通知静默。新权威事实若实质改变影响范围或风险判断，追加事件修订；仅来源增加或文字改写不构成重大修订。
5. 规范化或来源内容变更不得改写旧指纹、证据或用户已见通知；需要新指纹算法时升版本、保留旧记录并产生新的可审计运行。

重要性依据沿用 FR-Research-003：来源支持的事实有可能实质影响目标证券现金流、资本状况、上市/监管状态，目标市场利率、FX、流动性或风险环境，或直接改变已记录的策略失效/纸面计划风险时，才可列为重大。候选必须列出触发的规则和证据；只有情绪、重复标题或无证据的因果推论不满足门槛。

没有适用于所有市场和事件类别的统一金额/百分比阈值。若某类事件需要数值阈值，必须作为有来源、有适用期、有版本的规则定义；数据样本或来源不足时不生成数值门槛。Codex 可提出候选和影响说明，但不能补造事实、设置规则版本或改变确定性过滤结果。

## 通知选择与本机交付

每轮至多产生 3 条新的重大事件通知，排序完全沿用 FR-Research-005：

1. 直接触发已记录的纸面风险/策略失效条件；
2. 直接涉及目标证券或当前开放市场；
3. 来源质量与证据完整度更高；
4. 市场发生时间/来源发布时间更近；
5. 仍相同则按稳定事件 ID 排序。

排序输入、得分依据和未入选数量均可审计；同一输入和规则版本重跑结果一致。超额候选记 `DEFERRED_LIMIT`；后续只在仍满足新鲜度和重大性条件时递补，过期则记 `EXPIRED_UNNOTIFIED`。已通知事件的重复来源静默；只有实质重大修订可产生一条新修订通知。

通知仅写入本机 `notifications` 记录，不调用邮件、云推送或外部联系人。唯一键由事件 ID + 重大修订 ID 构成；同一事件修订无论由哪个扫描任务发现都只产生一次待读通知。通知决策、选中的通知、通知步骤成功状态和任务最终状态在一个短事务提交。来源水位可先于通知决策提交，但 pending 事件仍可被后续任务捞取；进程崩溃或重放均不会丢失或重复通知。未入选和过期的候选在 `notification_decisions` 留下原因、排序、规则版本和任务引用。用户已读状态只改变本机通知投影，不改事件事实或任务结果。

## 失败、重试和离线行为

- 请求按来源配置的有效期限结束，不允许无限等待。只有可重试的瞬时网络/服务错误可以重试，整个任务最多 3 次总尝试；凭据缺失、认证/权限/费用问题、日历/来源授权问题和不可恢复结构错误不自动重试，分别记录 `BLOCKED_EXTERNAL` 或真实失败原因。每次 Worker 认领的尝试都计入同一任务预算；显式 resume 不重置预算，预算耗尽后必须创建新任务并关联原任务。
- 尊重来源提供的 `Retry-After`；其他退避策略必须版本化并由实际连接器验证，不在本设计里臆造间隔。重试范围仅包含幂等步骤，并沿用任务键、输入 hash 与已提交检查点。
- `BLOCKED_EXTERNAL` 不自动重试；外部条件恢复后，只有显式本机 resume 命令可将同一输入的任务重新置为 `PENDING`。`FAILED` 在重试预算耗尽或遇到不可恢复错误后为终态；用户重新发起新运行须使用新的幂等键并关联原失败任务。
- 无凭据/网络/新闻/行情源时，本机已保存资料仍可读；相关来源为 `UNAVAILABLE`，任务为 `BLOCKED_EXTERNAL` 或真实运行失败，报告为 `NOT_VERIFIED` / `PARTIAL`。不可返回空事件列表作为成功的 `NO_NEW_EVENTS`。
- Fixture 只可用于隔离的演示/流程验证；所有派生通知和结果保持 `DEMO_ONLY`，不并入真实告警、来源水位或纸面账本。

## 手算验收案例

| 场景                                                        | 预期结果                                                                  |
| ----------------------------------------------------------- | ------------------------------------------------------------------------- |
| 周末或官方整日休市，目标市场均关闭                          | 任务 `SKIPPED`、结果 `SKIPPED_CLOSED`；不采集、不通知、不推进水位。       |
| TSE 11:30–12:30 午休，美国市场尚未开市                      | TSE 证券不扫描；不得显示“无新事件”。                                      |
| 纽约 DST 切换日，东京时间不变，NYSE/Nasdaq 当地开市时间不变 | 取当日官方版本日历和 IANA 时区换算；不使用固定 UTC 偏移。                 |
| 提前收盘或临时休市后日历来源不可用                          | 结果 `CALENDAR_UNAVAILABLE`，任务失败关闭；不根据常规钟点猜测仍开市。     |
| 同一计划槽位被两个定时触发重复投递                          | 唯一幂等键只产生一项任务，不重复扫描或通知。                              |
| 完整抓取两来源后进程在提交前崩溃                            | 水位与结果不部分推进；恢复后沿用同一任务键执行安全重试。                  |
| 一来源成功、另一必需来源超时                                | 仅完整来源推进自己的水位；结果为部分覆盖，不能报告 `NO_NEW_EVENTS`。      |
| 同一来源稳定事件 ID 的报道被转载，或原标题加追踪参数        | 归并证据、保持通知静默；新权威重大修订才产生一个修订通知。                |
| 本轮有 4 个合格新事件                                       | 依稳定排序通知前 3 个，另 1 个 `DEFERRED_LIMIT` 并保存递补/过期依据。     |
| 暂时性 5xx，连续执行重试；或凭据错误                        | 瞬时错误总尝试数不超过 3；凭据错误 `BLOCKED_EXTERNAL` 且尝试数不增加。    |
| 离线但有 Fixture                                            | 真实来源结果 `NOT_VERIFIED`；Fixture 展示结果 `DEMO_ONLY`，不伪装无事件。 |

## 后续验证边界

本 Issue 定义可执行、可复算的行为契约，不代表官方交易日历或任何新闻/行情提供商已经接入。日历版本、市场覆盖、来源权限、速率限制和 SLA 必须在 P04/P07 用官方来源及实际样本验证；Worker 调度、SQLite 原子认领与恢复由 P04/P05/P11 实现并由 P12 覆盖故障场景。
