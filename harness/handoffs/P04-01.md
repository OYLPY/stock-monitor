# P04-01 / #33 Handoff

## Objective

Verify the installed Codex TypeScript SDK's local CLI auth, streamed structured response, failure/quota behavior, and file boundary; acceptance is tracked in [Issue #33](https://github.com/OYLPY/stock-monitor/issues/33).

## Established facts

- `@openai/codex-sdk` and its bundled CLI are 0.169.0; the globally installed `codex` is 0.149.1. The SDK's default local executable is the bundled version.
- One real local-auth SDK request returned valid `{"status":"READY"}` JSON, with an empty read-only working directory.
- An empty temporary `CODEX_HOME` reports `not_logged_in`; the SDK turn failed with a generic network error, not an auth-specific error.
- With an isolated temporary home and non-secret local-only key, bare SDK offline mode issued 37 `/v1/responses` requests. Passing `features.unbounded_connection_retries=false` did not make this path satisfy NFR-004's maximum of three attempts.
- A candidate host policy aborted the SDK turn on its first streamed network error; that offline run issued three loopback requests and passed the bound. This evidence covers only the tested connection failure.
- A local simulated 429 fixture received two `/v1/responses` requests; the SDK classified the turn as `network_unavailable`. Real account quota semantics remain unverified.
